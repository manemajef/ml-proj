# Claude pipeline — findings and decisions

Companion doc for [claude.py](claude.py). Output: `data/Group_27_Submission_02.csv`
(15,866 rows, `Client_ID, Drop_Probability`, same format as the original
`Group_27_Submission.csv`).

## The one finding that drives everything

**The test set is strictly future data.** Train covers 2015-07-01 → 2017-04-26;
the test set covers 2017-04-26 → 2017-08-31 with essentially zero overlap.
That explains the midterm gap: random-split validation said **0.944** AUC, the
leaderboard said **0.886**. Random CV mixes past and future rows, so the model
gets credit for memorizing period-specific patterns that don't exist in the
future window.

Consequence: every model/feature decision here was made on a **chronological
holdout** — fit on rows before 2017-01-01 (51,822 rows), validate on the 2017
rows (11,642 rows, ~4 months, same window length as the test set). The
"lower AUC" the mini-notebook saw with time splits isn't a flaw of the split;
it *is* the honest leaderboard estimate.

## What's different from the original pipeline

| Aspect | Original (`notebook.py`) | This pipeline (`claude.py`) |
|---|---|---|
| Validation | Random 80/20 stratified split | Chronological holdout (last 4 months) |
| Categoricals | One-hot; Agent/Country collapsed to top-N; Company_ID dropped | Native categorical splits in LGBM/XGB/CatBoost + frequency encoding of Agent/Company/Country (train+test counts, label-free) |
| Date | Dropped entirely | Month/day-of-week/week seasonality **plus a linear `days_since_epoch` index** |
| Model | Single XGBoost (best of 3 on random split) | Rank-average blend of LightGBM + XGBoost + CatBoost |
| Text cleanup | Partial (cn→chn) | Full normalization: lowercase, strip, collapse whitespace, junk placeholders ("unknown", "-", "n/a"...) → NaN |
| Outliers | Caps on Students_Count/Practical_Hours/Tuition | Same idea (caps at 10 / [0,12] / 600) |

New engineered features: total participants, professional share, total hours,
practical-hours share, cost×hours, previous drop rate
(`Prev_Course_Dropouts/(Prev_Course_Attended+1)`), kits & tickets per
participant, got-requested-lab flag, has-company/has-agent flags.

## Chronological holdout results

| Config | Chrono AUC |
|---|---|
| LightGBM | 0.9106 |
| XGBoost | 0.9098 |
| CatBoost | 0.9095 |
| Blend of 3 | 0.9118 |
| LightGBM + time index | 0.9135 |
| XGBoost + time index | 0.9142 |
| **Blend of 3 + time index (chosen)** | **0.9157** |
| LightGBM, random split (reference) | 0.9618 — optimistic, ignore |

Tried and rejected:
- **Recency sample weights** (half-life 365d and 180d): neutral to slightly
  worse (0.9104 / 0.9115). The boosters already pick up the time trend via the
  index feature.
- **Dropping the date entirely** (the original approach): costs ~0.4 AUC
  points on the future window.

## The surprising bit: the time index helps

Intuition said "trees can't extrapolate, drop the date" (the original
notebook's call). The chronological holdout says the opposite: giving the
models `days_since_epoch` **improved every one of them** on strictly-future
validation data. Why: future rows fall past every split threshold, so they all
land in the *most recent* leaf — the model effectively says "score future rows
like the latest regime," which beats averaging over 2015–2016 behavior. This
was validated under real extrapolation (fit ends Dec 2016, validation is 2017)
before being trusted for the submission.

Also kept, deliberately: `Payment_Terms` (the suspiciously strong
"Prepaid (Non-Refundable)" signal). It held up in the 2017 validation window,
so whatever generates it persists over time — no reason to believe it breaks
in the following four months.

## Final submission

All three boosters retrained on the full 63,464 labeled rows with the time
index, predictions rank-averaged (preserves each model's AUC ordering,
ignores calibration disagreements), written to
`data/Group_27_Submission_02.csv`. Correlation with the original submission's
probabilities: 0.95 — similar overall ranking, but the disagreements are
exactly where the temporal handling differs.

## Head-to-head: old pipeline vs new, same splits

To make the comparison apples-to-apples, the original notebook.py pipeline
(imputation, date dropped, top-N agent/country collapse, one-hot, XGBoost
300×5) was re-implemented and scored on the exact same splits as the new
pipeline (scratch script, not committed):

| Pipeline | Random 80/20 AUC | Chrono holdout AUC |
|---|---|---|
| Original (notebook.py approx) | 0.9402 (notebook itself: 0.9446) | 0.9049 |
| New (claude.py blend + time) | 0.9621 | 0.9155 |

The 0.9402 vs 0.9446 gap confirms the re-implementation is faithful. The new
pipeline wins on **both** protocols — +2.2 AUC points on the naive random
split and +1.1 on the future-window split.

**Leaderboard estimate:** the old pipeline scored 0.9049 on the chrono holdout
but 0.8864 on the real leaderboard — a ~1.9-point optimism gap (the real test
window is further in the future than the holdout window). Applying the same
gap to the new pipeline's 0.9155 gives an expected leaderboard AUC of roughly
**0.90 ± 0.01**. Not a guarantee — drift May–Aug 2017 is unobserved — but the
relative improvement was measured under the leaderboard's own protocol.

Reproduce: `python claude.py experiments` (prints the table above),
`python claude.py final` (writes the submission).
